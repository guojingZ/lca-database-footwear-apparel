# 从“一个数据库”到“能使用的工序资料”

## 1. 它到底是什么

这是鞋服生命周期评价的公开文件库，不是需要先安装的数据库服务。CSV 提供已经计算出的影响结果，Markdown/PDF 提供工艺、边界、来源和部分建模说明。原仓库唯一 Python 脚本负责发布资料到 Zenodo，并非服装核算引擎。

可以把一条记录理解为：“某种材料采用某项代表工艺，生产指定单位产出时，对环境造成多少影响”。例如常规喷射分散染色记录的 GHG 为 `4.788708973517695 kg CO₂e/kg`。这是该记录的已发布气候影响值，不是每 kg 染料的排放，也不是整件衣服的结果。

证据：[染色 CSV](../upstream/carbonfact/datasets/dyeing/impact-scores.csv)，描述符末段为 `DISPERSE/BATCH/CONVENTIONAL_JET#SYNTHETIC_FIBERS@WORLD`。

## 2. 四个常用词

| 词 | 中文理解 | 在项目里怎么用 |
|---|---|---|
| 功能单位 | 一条结果对应“多少、什么产出或服务” | 染色通常 1 kg；运动鞋装配 1 双；熨烫 1 分钟 |
| 活动量 | 你的产品实际发生多少相关活动 | 染色对象产出 kg、运输 tkm、熨烫分钟 |
| 影响因子 | 每功能单位已经计算好的环境影响 | 用活动量乘 GHG；不能任意换材料/地点 |
| 系统边界 | 已包含和排除哪些材料、操作、服务 | 防止漏算、重复算，并解释结果的小计范围 |

`0.2 kg 产出 × 4.788708973517695 kg CO₂e/kg` 可以估算对应加工排放。产品质量链有损耗时，这里的 0.2 kg 未必等于成衣净质量，应沿工序链反推。

## 3. 先按业务工序读

不要先背 16 个指标。先选你熟悉的工序，例如染色，读 [工序卡](processes/dyeing.md)，再在页面找对应材料、技术和色深。点“数值与来源”，同时看中文名、原始标识、功能单位、范围和证据。

你自己的“标准工序”可以独立维护：如“涤纶常规喷射分散染”，映射到具体 Carbonfact 描述符；匹配理由应说明对象、设备、染料类别、单位和边界。一个中文工序名可能有多个候选记录，不能仅凭名字自动批准。

## 4. 可以深挖到哪里

| 层次 | 已公开的内容 | 还不能据此保证什么 |
|---|---|---|
| 结果 | 304 条记录、16 项影响值 | 不能由总 GHG 唯一反推全部用电/热/化学品量 |
| 工序 | 工艺对象、条件、范围、限制 | 不等于实际工厂配方 |
| 前景建模 | 部分参数、计算公式、文献和清单说明 | 开放深度因工序而异，不一定每条都有完整量化清单 |
| 背景映射 | ecoinvent 等背景活动名称、代理逻辑 | 有名称不代表取得底层数值或完整访问权限 |
| 再计算 | 部分解释可学习和自建 | 当前快照不能保证完整复现原始 Brightway 模型 |

染色的附录名为 Full LCI，但活动分类与参考产品不等于完整逐交换投入量。化学品说明也没有重列全部助剂的 GHG。详见 [染色卡](processes/dyeing.md)及 [已知差异](已知差异.md)。

## 5. 为什么模板里会有缺项

棉纺纱记录计算纺纱加工，不提供有机棉或再生棉原料生产结果。当前库也没有能直接匹配模板棉漂白的结果记录。运输、配件、包装及损失材料处理需要按你声明的范围补齐；同时核对是否已经被具体因子包含。

默认 T 恤的约 1.75876 kg CO₂e/件只是当前工序组合的已覆盖小计，不能与截图里另一套模型的总值直接作对照。模板重量、材料比例和未知前处理投入比是结构演示，需替换成你的产品事实。

## 6. 怎样开始使用自己的产品

1. 确定是核算“原料到成衣出厂”，还是只核算“坯布进入到染整出厂”。
2. 填成品净质量，列主布材料和工序顺序。
3. 对照工序卡与原文选因子；不能匹配的环节先留空。
4. 根据真实投入产出比或有依据的损耗率传递数量。
5. 补外部材料、能源、废物等因子，记录来源和范围；审阅后才标记已审阅。
6. 看小计、缺项、证据，保存模型。数据充分后再宣称所声明边界完整。

接到自己的软件时，直接复用本项目数据接口与 Python 引擎；企业投入路径先用 [inventory.json](../examples/inventory.json)，不要先改变现有研究项目。
