# 开发接续与接入自己的项目

## 运行环境与结构

Python 3.10+，标准库即可运行。网页使用原生 HTML/CSS/JavaScript，没有构建步骤。服务固定绑定本机 `127.0.0.1`，不上传模型，不写入服务器上的用户数据；保存/加载是浏览器本地 JSON 操作。

| 模块 | 权威职责 |
|---|---|
| `carbonfact_app/catalog.py` | 原值、归一字段、来源校验、目录版本 |
| `carbonfact_app/engine.py` | Decimal 计算、单位换算、完整性、比较、导出 |
| `carbonfact_app/templates.py` | 三类业务结构模板，不补虚构数据 |
| `app.py` | 本地 HTTP，参数 `--port`、`--no-browser` |
| `web/app.js` | 表单、选择、证据、结果展示与下载 |
| `tools/data_workbench.py` | audit / build / validate |
| `tools/calculate.py` | 复用引擎的 JSON 命令行核算 |
| `tools/prepare_upgrade.py` | 默认只盘点，执行时只备份匹配旧文件 |

## 直接读取数据

本轮用 JSON/CSV，不需要数据库服务。你的项目可以自行导入 SQLite/PostgreSQL，但保存 `descriptor`、功能单位、边界、来源与数据版本，不能只留中文名和 GHG。

```python
from carbonfact_app.catalog import load_catalog

catalog = load_catalog()
candidates = [f for f in catalog["factors"] if f["category"] == "dyeing"]
for factor in candidates:
    print(factor["activity_zh"], factor["unit"], factor["impacts"]["GHG"])
```

候选筛选不等于因子审批。可在你的系统建立 `standard_process_id → descriptor + 适用条件 + 审阅依据`，再交给活动数据计算。当前 v0.1 未持久化通用企业标准工序映射，产品模型保存的是实例选择。

## 直接调用核算

```python
import json
from pathlib import Path
from carbonfact_app.catalog import load_catalog
from carbonfact_app.engine import calculate

model = json.loads(Path("examples/factory.json").read_text(encoding="utf-8"))
result = calculate(model, load_catalog())
print(result["status"], result["subtotal_ghg"], result["missing"])
```

从其他工程调用时，把本项目根目录作为模块搜索路径或建立你自己的封装，不复制另一套核算规则。模型格式见 examples 三个 JSON；不是 SQL 数据库转储。

## 模型字段合同（schema_version=1）

| 对象 | 字段 / 约定 |
|---|---|
| 产品 | `name`、`weight_g` 字符串、`result_basis=item/batch`、`boundary`、`boundary_reviewed`、`catalog_digest` |
| 材料 | `include_materials`；`materials[]` 含 name、share_percent、factor_id |
| 工序 | `chain[]` 顺序上游到下游，id 唯一；name、mode、factor_id、ratio_mode |
| 数量依据 | ratio_mode=factor；或 ratio + input_ratio + ratio_note；或 loss + loss_percent + ratio_note |
| 工序清单 | mode=inventory 时 factor_id=null；inventory[] 每 kg 产出 quantity/unit/factor_id；inventory_complete |
| 审阅依据 | `repeat_reason` 真实重复加工；`overlap_review` 边界不重叠证据 |
| 必需工序 | `required_stages[]` 的 id/name；删除链实例不会自动删除必需项 |
| 外部因子 | `external_factors[]`：唯一 ext- id、name、ghg、unit、source、scope、kind、status |
| 外部类型/状态 | kind=material/process；status=reviewed/pending/hypothetical |
| 损失材料 | `waste_factor_id`；按 kg 统一处理路线，缺失 null |
| 独立项目 | `additional_items[]`：id/name/quantity/unit/factor_id；可填 excluded_reason 表示明确排除 |

数值保存建议用十进制字符串，空缺用 null。清单数字为“每 kg 本环节产出”；独立项目数字为每件或本批次，必须区分。UI 的高级 JSON 入口用于明确调整必需范围和复杂依据，不能用它绕过业务复核。

## HTTP 接口

| 方法与路径 | 请求 | 响应 |
|---|---|---|
| GET `/api/health` | 无 | 版本、目录摘要 |
| GET `/api/catalog` | 无 | 完整整理目录及署名 |
| GET `/api/templates` | 无 | 三个结构模型 |
| POST `/api/calculate` | `{"model": {...}}` | 结果、活动量、分项、缺项和错误 |
| POST `/api/compare` | model、baseline | 两结果、可比状态及差值 |
| POST `/api/export` | model | 模型、结果、所选公开记录和署名 |
| GET `/evidence/<相对路径>` | 只读限定来源/docs/processed | 原文资料，路径受限 |

输入格式错误为 400；模型业务错误通常为 200 且 `valid=false`，调用方必须检查状态。POST 体上限 2 MB。网页不请求外部服务，证据的官方链接由用户打开。

## 修改数据与更新上游

修改中文映射/元数据后：build → validate → 重新匹配模型 → 运行相关测试。目录变化会导致现有 examples 的 digest 过期，确认后通过 templates 重新导出，不静默改用户保存模型。

更新上游要保存新来源、登记版本和差异、确认中文映射覆盖新描述符、核对单位与边界，再生成新来源基线。不能把 source_manifest 改成当前坏数据哈希来“修复”失败。

本包没有原仓库发布工作流放在根 `.github/`；旧工作流已保留为快照。若以后发布自己的应用，应新建明确面向应用的流程，不自动沿用 Zenodo 发布脚本。

## 校验命令

```powershell
python tools/data_workbench.py validate
python -m unittest discover -s tests -v
python tools/calculate.py examples/factory.json --export --output local-data/factory-model.json
```

Python 测试不要求 Node。可选界面逻辑检查见 [验收报告](验收报告.md)；真实浏览器的布局和 Windows 启动需在对应环境验收。

## v0.2.0 新人学习与独立演示

`carbonfact_app/learning.py` 维护概念/导学和参数白名单，使用旧模板与同一引擎组装教学模型；没有修改 engine.py 的规则。`web/learning.js` 提供入门与案例；`web/demo.js` 在独立页面保存参数、学习进度和复核意见；`web/reader.js` 只渲染安全的 Markdown 子集。

| 接口 | 合同 |
|---|---|
| GET `/api/learning` | 概念卡、六步导学、七步演示定义、实际模板与结果 |
| POST `/api/demo/calculate` | `{"state": {...}}`，返回按白名单参数组装的 model、result、comparison、缺项建议 |
| POST `/api/demo/export` | 同上，返回 packet 与中文 markdown；错误输入不导出 |
| GET `/api/document?path=...` | 限定来源/docs/processed 下的 Markdown 文本、路径与 SHA256 |
| GET `/demo`、`/reader` | 独立演示与资料阅读页面 |

演示 state 支持 task、weight_g、organic_share、recycled_share、scenario、dyeing_selected、review_note、review_status、catalog_digest。scenario 为 baseline/weight_double/shares_80_20/loss_20；复核状态仅是教学反馈，不改变业务 complete 状态。

JSON 包仍是 carbonfact-zh-model，保留原 model 合同；demo_state/demo_ui/demo_trace 是演示信息。演示导入按参数重建并核对模型一致性，自定义产品由原工作台加载。

浏览器存储键：carbonfact.concepts.v1 与 carbonfact.demo.v1。演示不写服务器文件，不共享工作台当前模型。实际接口和逻辑检查见 tests/test_learning.py、tests/experience_smoke.cjs；后者模拟 DOM，不代表浏览器布局。

整理目录内部 app_version=0.1.0 是数据整理基线，目录摘要未变；当前应用版本看 `/api/health` 的 version=0.2.0。
